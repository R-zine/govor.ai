## Failed harness attempts

The first temporary Godot wrapper used `Start-Process` and received an empty `ExitCode`, so it
rejected the export instead of accepting an invented status. Only its empty staging directory was
removed before retry. The corrected wrapper owns a `System.Diagnostics.Process`, reads both output
streams asynchronously, waits under a bounded deadline, and checks its actual integer exit code.
The override was confined to the packaging process; tracked build scripts were unchanged.

An initial standalone APK verifier lacked the configured JDK and failed before installation;
setting `JAVA_HOME` to the project's Android Studio JDK allowed normal verification. A supplemental
embedded-Python smoke initially joined `PYTHONPATH` incorrectly and failed to import the domain;
the corrected path-list join passed. A later metadata-only PowerShell pipeline did not enumerate
the JSON artifact array; assigning it before filtering corrected the report. None of these failed
harness attempts is counted as a pass or changed the signing identity, learner data, or source.
